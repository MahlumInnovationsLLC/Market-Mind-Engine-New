A clean three-state switch via `AXIOM_LLM_MODE` env var:
- `cloud` (default) — current OpenAI + Anthropic mix
- `local` — every persona rerouted to Ollama on Mac Studio
- `hybrid` — fast personas local, reasoning personas cloud

Implementation details that show this was done right:
- **Provider-aware fallback** in `_FALLBACK_BY_PROVIDER` — if local Ollama dies, falls back to cheapest hosted (`gpt-4o-mini`) so the swarm never goes silent
- **Per-persona-id mapping** for fast vs reasoning models — `_apply_llm_mode` is auditable, not magic
- **`active_llm_mode_state()` is exposed read-only via runtime settings** — operators can grep/curl to confirm which providers will be hit without reading logs
- **Gatekeeper override is ignored under `local` mode** — explicit comment: "local is a hard switch, not a polite suggestion"

This is the difference between **$80–$200/mo cloud LLM bill** and **$0/mo on Mac Studio**, with zero code changes when flipping. A switch flip.

## Part 5 — Honest Concerns

### Concern #1: 598,218 of 603,128 V1 archive rows (99.2%) are `UNKNOWN` league
The V1 backtest report's headline numbers are real, but they apply to 4,910 rows. The other 598k are stuck in calibrator-bypass mode because V1's archived rows don't have a clean `league` field for them. This is a **data-engineering problem**, not a model problem, but it's worth knowing: until those rows get league-tagged, the "we beat V1" claim covers ~0.8% of historical trades by row count. The improved leagues do happen to be the highest-volume ones in your live feed, so the operational impact may be larger than the row count suggests, but be precise about it in the deck.

**Mitigation:** Land issue #731 + a one-shot league-inference backfill on V1 archive rows. Then re-run the harness; expect the headline to flip to "603k rows, X improved, Y regressed, Z parity."

### Concern #2: Calibration sample counts are thin in some leagues
NHL has 300 samples, MLB 163, MLS 1, F1 / WTA / ATP / UFC / soccer leagues not represented in the backtest at all. Isotonic regression on <500 samples is wobbly. Action: prioritize ingesting more historical data for thin leagues OR mark those calibrators as low-confidence in the dashboard.

### Concern #3: Paper fill simulator still optimistic
Until [Round 11 Bug #5](workspace://paper-live-toggle-audit.md) is fixed, every paper Brier you compute is biased low because paper always fills 100% at limit. This contaminates `online_learning_buffer` and biases live calibrators. **Fix this before the next paper-cycle benchmark run** — your numbers will look slightly worse but they'll be honest.

### Concern #4: Trade-gated learning ceiling
Learning loops only fire when trades settle. If you go quiet for a week, calibrators stagnate. The Round 13 shadow-prediction layer is the architectural fix. This is also a *defensible moat* feature — no consumer app has it — so it's worth shipping for the pitch deck.
